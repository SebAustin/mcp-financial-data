# ADR 0002 — Target MCP specification 2025-11-25 with streamable HTTP transport

* Status: Accepted
* Date: 2026-05-17
* Deciders: Sebastien Henry

## Context and Problem Statement

The Model Context Protocol has versioned spec releases. We need to pick
**one** target spec version and one transport for the W1 sprint. The choice
affects: which client implementations can connect, whether OAuth 2.1
flows are first-class, and which features (MCP Apps inline UI, dynamic
capability negotiation) are available.

## Decision Drivers

* The 10-K extractor demo needs MCP Apps inline UI, which is GA in the
  2025-11-25 spec.
* OAuth 2.1 dynamic client registration is a key differentiator for the
  Anthropic FDE anchor; it requires HTTP-based transport (not stdio).
* Hiring managers will paste a Claude Desktop / Cursor / Goose handle;
  these clients all support streamable HTTP as of May 2026.

## Considered Options

* **Target 2025-11-25 + streamable HTTP.** Latest GA at sprint start.
* **Target 2025-06-18 + stdio.** Older but simpler; loses MCP Apps UI and
  OAuth flows; would force a re-platform for P9 deployment.
* **Multi-version (auto-detect).** Adds complexity; doubles the test matrix.

## Decision Outcome

Pin the spec target to **2025-11-25**, transport to **streamable HTTP**.
Document this in the README + AGENTS.md so contributors don't accidentally
use stdio idioms.

## Consequences

* Clients pinned to older spec versions cannot connect (acceptable —
  the demo controls its client).
* OAuth 2.1 RS implementation lands in W1 (`prompts/01_oauth_resource_server.md`)
  rather than being deferred.
* The capability advertisement at startup must include `tools.listChanged`
  and the `ui` capability.
